# uNews 0.3.9

Текущая версия: `0.3.9` — uNews исправляет две фактические проблемы очереди, найденные после проверки писем GitHub Actions:

- `news/README.md` больше не считается патчноутом;
- `type: documentation` теперь принимается как документационное обновление.

## Что исправлено

### 1. Служебные Markdown-файлы в `news/`

До `0.3.9` сканер брал любой `.md` из папки `news/`. Из-за этого `sunpole/uImposition/news/README.md` попадал в очередь и давал ошибку:

```text
Patchnote has no YAML front matter
```

Теперь в очередь попадают только Markdown-файлы с именем датированного патчноута:

```text
YYYY-MM-DD-*.md
```

Это сохраняет возможность держать в `news/` служебные README/документы, не превращая их в Telegram-посты.

### 2. Тип `documentation`

До `0.3.9` policy-слой поддерживал `docs`, но не поддерживал `documentation`. Из-за этого патчноут `uDream 23.8.8` блокировался ошибкой:

```text
Unsupported type: documentation
```

Теперь `documentation` разрешён и получает то же поведение, что `docs`: обязательная фраза `Документационное обновление.` добавляется автоматически, если её нет в коротком тексте.

## Регрессия

Добавлены проверки:

- датированный `YYYY-MM-DD-*.md` считается публикуемым патчноутом;
- `README.md` не считается патчноутом;
- недатированный `.md` не считается патчноутом;
- `.png` не считается Markdown-патчноутом;
- `type: documentation` проходит policy-слой;
- source-check закрепляет новый queue scanner predicate.

## Не изменено

- строгий FIFO и порядок версий внутри проекта;
- максимум 20 публикаций за запуск;
- пауза не менее 61 секунды;
- image integrity проверка через GET, CRC, zlib и повторную проверку перед Telegram;
- Telegram-safe PNG normalization из `0.3.8`;
- secret redaction и запрет реальной локальной публикации.

## Следующий шаг

`0.3.10` можно посвятить более ясному состоянию очереди в `health.json`: отдельно показывать `bot_failed`, `queue_has_errors` и `nothing_ready`, чтобы письма GitHub Actions было проще читать.
